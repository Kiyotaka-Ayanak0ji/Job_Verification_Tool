## 7. Loading States & Error Handling Gaps

### 7.1 Missing Loading + Error Handlers

| Slice | Thunks With `pending`/`rejected` Cases | Thunks Missing Error Handling |
|---|---|---|
| `authSlice.js` | `login`, `signup` only | `fetchMe`, `updateProfile`, `changePassword` — no `pending`/`rejected` cases. Failures silently leave state unchanged. |
| `reportsSlice.js` | `fetchReports` only | `verifyCompany`, `patchReport`, `removeReport`, `getReport` — no `pending` or `rejected` handlers. |
| `adminSlice.js` | `fetchUsers` only | `patchUser`, `deleteUser`, `fetchAnalytics` — no `pending`/`rejected` cases. |
| `billingSlice.js` | `fetchBillingStatus` only | `startCheckout`, `manageBilling` — no `pending`/`rejected` cases. |
| `groupsSlice.js` | All 4 thunks | (Complete) — `pending`/`rejected` handled for all. |
| `usageSlice.js` | None | `fetchUsage` — no `pending`/`rejected` cases. |
| `mlAdminSlice.js` | None | Every thunk lacks `pending`/`rejected` cases. |

**Impact**: When `getReport` fails (e.g., network error, 404), `JobDetails.jsx` has no way to distinguish loading from error — it only checks `if (!current) return <Loading>`. If the request fails, `current` stays stale or null with no error UI.

### 7.2 `JobDetails.jsx` — No Error State

```js
useEffect(() => { dispatch(getReport(id)); }, [dispatch, id]);
if (!current) return <Loading />;
const { report, verification, job } = current;
if (!report) return <NotFound />;
```
- No `loading` check — if `getReport.fulfilled` hasn't fired yet, `current` is `null` and the skeleton shows. But if `getReport.rejected` fires, `current` remains `null` and the skeleton shows indefinitely with no error message.

### 7.3 `Dashboard.jsx` — Two Unawaited Dispatches

```js
async function onDelete(id) {
  if (!confirm("Delete this report?")) return;
  await dispatch(removeReport(id));   // awaited — OK
  toast.success("Report deleted");     // shown regardless of internal state
}

async function move(reportId, groupId) {
  await dispatch(patchReport({ id: reportId, patch: { groupId: groupId || null } }));
  // No try/catch, no toast, no error feedback to user
}
```
- `move()` has **no error handling at all** — if the patch fails, the user gets no feedback and the group dropdown silently reverts.
- `onDelete()` always shows success toast even though `reportsSlice.removeReport` has no `rejected` handler (it silently fails).

### 7.4 `AdminAnalytics.jsx` — Polling with No Error Path

```js
async function load() {
  try {
    const { data } = await api.get("/admin/ml/analytics");
    if (alive) setData(data);
  } finally { if (alive) setLoading(false); }  // ← errors are swallowed
}
```
- Errors are caught by `try/finally` but never surfaced — `toast.error` is never called, the stat tiles just show `—`.

### 7.5 `Skeleton.jsx` — `className` Props Silently Dropped

The `SkeletonText` and `SkeletonButton` components **do not accept `className` as a prop**:

```jsx
// SkeletonText — no props parameter at all:
export const SkeletonText = () => ( ... )

// SkeletonButton — only accepts `size`, not `className`:
export const SkeletonButton = ({ size = "p-2 px-4" } = {}) => ( ... )
```

All `className` props passed to these two components in `Dashboard.jsx` (lines 82, 83, 92-94, 98, 112-116) and `Results.jsx` (lines 27, 28, 31) are **silently ignored**. The skeleton text always renders at fixed width (`w-32`), and the skeleton button ignores sizing props like `h-8 w-8`.

### 7.6 `Home.jsx` — Skeleton Container Side Effect

```js
const skeletonContainer = document.createElement('div');
skeletonContainer.className = 'animate-pulse';
document.body.appendChild(skeletonContainer);
// ...
skeletonContainer.remove();
```
- This creates a detached DOM node, appends it to `<body>`, and removes it on completion/error. It's an unusual pattern — the `animate-pulse` div is empty (no children rendered into it) and serves no visible purpose. It's dead code that manipulates the DOM unnecessarily.

### 7.7 `Skeleton.jsx` — Module-Level DOM Mutation

```js
const style = document.createElement('style');
style.textContent = ` @keyframes shimmer { ... } `;
document.head.appendChild(style);
```
- This runs at **module import time**, not inside a `useEffect`. It mutates `document.head` during module evaluation. While modules are singletons so it runs once, this is a side-effect at import and violates React's component lifecycle patterns. If a strict CSP blocks `document.createElement('style')`, the shimmer animation breaks silently.

### 7.8 `Profile.jsx` — No Loading / Error States for Billing

```js
const { data: billing, loading: billingLoading, error: billingError } = useSelector((s) => s.billing);
```
- `billingLoading` and `billingError` are destructured but **never used** in the JSX. The quota cards and billing section render with stale/empty data during loading.

## 8. Miscellaneous Issues Found

### 8.1 Production Favicon Path

`index.html` line 5:
```html
<link rel="icon" href="./src/assets/images/icon.png" />
```
- In production (`vite build`), files under `src/` are bundled, not served at their original path. This favicon will 404. Should reference a public asset (e.g., `/favicon.ico` or `/favicon-96x96.png`) or use an imported URL.

### 8.2 PWA Manifest Mismatch

`index.html` line 8:
```html
<link rel="manifest" href="/manifest.webmanifest" />
```
- The `public/` directory contains `site.webmanifest`, not `manifest.webmanifest`. The VitePWA plugin generates `manifest.webmanifest` at build time, but in dev mode this file doesn't exist, causing a 404 on the manifest.

### 8.3 Debug Console Statements

`api/client.js` lines 23–25:
```js
//Testing 
console.log("Token: ", token);
console.log("Request: ", cfg.url);
```
- Leftover debug logging in the request interceptor. Logs every API request URL and token to the console in production builds.

### 8.4 Duplicate Icon in AppShell Menu

`AppShell.jsx` lines 76–77:
```jsx
<MenuItem icon={BarChart3} to="/admin/analytics" ...>Analytics</MenuItem>
<MenuItem icon={BarChart3} to="/admin/reports" ...>Reports</MenuItem>
```
- Both "Analytics" and "Reports" menu items use the same `BarChart3` icon. Should use distinct icons (e.g., `FileText` for Reports).

### 8.5 Client-Side PDF Generation Without Server Validation

`JobDetails.jsx` `onExport()` (line 36):
```js
await api.post(`/reports/${report._id}/pdf-export`);
exportReportPdf(report, verification);
```
- The server endpoint is called (presumably for quota tracking) but the actual PDF content is generated **fully client-side** from whatever data is in the Redux `current` state. If the client data is stale or incomplete, the exported PDF won't match the server record. There is no server-generated PDF fallback.

### 8.6 `useNavigate` Unused in `JobDetails.jsx`

The component imports `useNavigate` but always uses `<Link>` or `return` navigation. It could use `navigate(-1)` in the back link instead of `<Link to="/dashboard">`, but as-is the import is simply dead.

## 10. Key Findings Summary

1. **Fully dead Redux slice**: `mlAdminSlice.js` (10 thunks, registered in store) is never used — all admin ML pages call `api.*` directly.
2. **Unused `apiMethods`**: 16 of 17 methods in `api/client.js` are never called. Only `fetchFeedbackByVerificationIds` and `toggleFeedbackInclude` are used.
3. **Unused thunks**: `fetchAnalytics` (adminSlice), `renameGroup` (groupsSlice).
4. **Unused skeleton exports**: `SkeletonAvatarText`, `SkeletonCard`, `SkeletonTableRow`, `SkeletonListItem`, `SkeletonProfileSection` are never imported.
5. **Unused imports**: `SkeletonText`+`SkeletonAvatar`+`SkeletonButton` in `Home.jsx`; `SkeletonAvatar` in `Results.jsx`; `useNavigate` in `Pricing.jsx` and `JobDetails.jsx`; `billingLoading`+`billingError` in `Profile.jsx`.
6. **Unused dependency**: `recharts` is installed but never imported.
7. **Debug logging**: Console.log statements in `api/client.js` request interceptor (lines 23–25).
8. **Module-level DOM mutation**: `Skeleton.jsx` injects a `<style>` tag into `document.head` at import time.
9. **className dropped**: `SkeletonText` and `SkeletonButton` don't accept `className` props — all className props passed to them are silently ignored.
10. **Error handling gaps**: 24 of 31 total thunks across all slices lack `pending`/`rejected` handlers, meaning loading and error states are not tracked for most async operations.
11. **Production favicon broken**: `index.html` references `./src/assets/images/icon.png` which won't resolve after `vite build`.
12. **Stale `current` in JobDetails**: If `getReport` fails (network error, 404), there is no error UI — the component stays in the loading state indefinitely.
13. **No error feedback**: `Dashboard.jsx` `move()` function dispatches a thunk with no error handling; `onDelete` functions across pages always show success toast without checking result.
14. **Google OAuth stub**: `Profile.jsx` has a disabled "Link Google (coming soon)" button — acknowledged placeholder.
